# 版本与功能差异详解

本文按版本逐个说明更新内容、能力差异与适用场景。

---

## 一、完整更新日志

### 5.1.0.x（2026-11-08）

写权限检查改为读取容器内 `/proc/mounts`，判定每个目录**实际所在挂载点**与**真实只读状态**，并说明「Docker 的 RW=true 只是 bind 参数，不代表底层文件系统可写」。

**解决的场景**：`docker inspect` 显示 `RW=true`，但容器内写文件仍报 `Read-only file system`。这种情况通常是嵌套挂载（网络共享）没有被带进容器。

### 5.0.0.x（2026-11-08）

- 新增「检查写权限」按钮：对媒体库实际目录做**真实写入测试**（创建临时文件再删除），明确判定只读挂载 / 无写权限 / 目录不存在，并给出宿主机可执行的具体命令
- 结果说明列改为可换行显示全文，不再被省略号截断（原 `cs-ellipsis` 限制 280px）

### 4.9.0.x（2026-11-08）

- 结果说明改为**累加**：移动文件失败不再覆盖「写入名称」与「刮削」的结果
- 汇总展示三件事各自是否完成：Jellyfin 名称已改 / 磁盘文件已改 / 已排队刮削

**解决的场景**：之前只改名称成功、磁盘改名失败时，说明只剩一条失败信息，看不出名称其实已改好。

### 4.8.0.x（2026-11-08）

修复刮削失败「无法构造 MetadataRefreshOptions」，两处都写错了：

| 项 | 错误的写法 | 正确写法 |
|---|---|---|
| 命名空间 | `MediaBrowser.Controller.Entities` | `MediaBrowser.Controller.Providers` |
| 构造函数 | 无参 `Activator.CreateInstance` | 必须传 `IDirectoryService` |

现从容器注入 `IDirectoryService`，并设置 `ReplaceAllMetadata = true`、`ForceSave = true` 强制全量重刷。

同时：磁盘改名失败时，对 `Read-only file system` / `Permission denied` 给出可执行的排查提示。

### 4.7.0.x（2026-11-08）

- 修复搜索失效：媒体库文件清单统一从界面读取筛选 / 媒体库 / 每页状态，不再被重置覆盖
- 两个开关各自独立判断是否需改动

**4.7 之前的问题**：判断是否要动作时只看 Jellyfin 名称：

```csharp
step.Renamed = changed && target != item.Name;   // 旧逻辑
```

如果 Jellyfin 名称恰好已等于目标名，就判定「无事可做」直接跳过，**连磁盘文件也不改**。

4.7 起分开判断：

```csharp
var nameNeedsChange = RenameWriteName && target != item.Name;
var diskNeedsChange = RenamePhysicalFiles && target != diskName;
step.Renamed = nameNeedsChange || diskNeedsChange;
```

### 4.6.0.x（2026-11-08）

修复「同时重命名磁盘文件」不起作用，两个叠加原因：

1. **开关没传到请求**：执行时后端只从数据库读设置，而该开关只有点「保存」才写库。现在三个开关随请求一起提交，后端以请求体为准
2. **失败被静默吞掉**：原 `RenamePhysicalFile` 返回 `bool`，五处直接 `return false` 不说明原因。现返回失败原因字符串

失败原因覆盖：路径为空 / 文件不在（含具体路径与扩展名）/ 目录不可访问 / 目标已存在 / 移动异常（含异常类型）

预演也会明确写出：`磁盘文件：(MAXING)(6666-1105) → 6666-1105` 或 `磁盘文件：不改`。

### 4.5.0.x（2026-11-08）

正则规则支持**捕获组提取**：替换文本留空时自动取第一个非空捕获组，也可用 `$1`/`$2`/`${name}` 指定。

**解决的需求**：不想写任何字面替换文本，只保留括号里的内容。

| 源名 | 规则 | 结果 |
|---|---|---|
| `(MAXING)(6666-1105)` | `\((6666-[0-9-]+)\):` | `6666-1105` |
| `(MAXING)(6666-1105)` | `\(([A-Z]+)\)\(([0-9-]+)\):$2` | `6666-1105` |

### 4.4.0.x（2026-11-08）

设置页新增「媒体库文件清单」表：

| 列 | 可排序 |
|---|---|
| 磁盘路径 | 是 |
| 磁盘影片名称 | 是 |
| 修改日期 | 是 |
| 大小 | 是 |
| Jellyfin 名称 | — |
| 状态（名称不一致标记） | — |

数据实时从磁盘读取（`FileInfo` 拿真实修改时间与字节数），不走索引缓存。支持媒体库下拉、关键词筛选、分页。

### 4.3.0.x（2026-11-08）

三处改动：

1. **改名与刮削拆分**：`RunMode` 枚举 `RenameOnly` / `ScrapeOnly` / `RenameThenScrape`，界面按钮拆成「只改名」「只刮削」
2. **源名称改取磁盘文件名**：
   ```csharp
   var diskName = item.FileNameWithoutExtension;   // 磁盘实际文件名
   var (target, changed, rule) = RenameEngine.Apply(diskName, rules);
   ```
   读：磁盘文件名 → 算：按规则 → 写：Jellyfin 名称 / 磁盘文件名
3. **重命名卡片增加媒体库选择**，选择随设置保存

同时修复预演返回 `undefined`（后端 PascalCase 与前端 camelCase 双写兼容）。

### 4.2.0.x（2026-11-08）

修复预演/执行返回 HTTP 400。

原端点用 `[FromBody] SomeClass` 强类型接收，模型绑定阶段就失败，且响应体是 `{errors: {"$.x":["..."]}}` 格式，前端只读 `error` 字段，只显示「请求失败：HTTP 400」。

现改为 `JsonElement` 手动宽松解析：

- 字段名大小写都认
- `bool` 接受 `true`/`false`/`"true"`/`"1"`
- `rules` 只取需要的字段，`pattern` 为空自动跳过
- 整体 try/catch，出错返回 `500 + 具体异常`

前端 `makeHttpError` 现解析三种响应体格式，失败原因直接写进结果表格。

### 4.1.0.x（2026-11-07）

修复全表格文字看不清。

**根因**：插件页从来没有自己的背景层。`app.css` 里定义了 `--cs-bg`，但从未应用到 `html`/`body`/`.cs-page`/`.cs-card`。卡片和表格底色是空的（透明），文字颜色只能靠宿主主题推断 —— 深色主题深底深字，浅色主题浅底白字，**两种情况都会看不清**。

**修法**：为 `html`/`body`/页面/卡片/表格/输入框/弹窗设定完整的背景与前景，全部使用主题变量；主题判断改为读宿主实际背景色亮度。

### 4.0.0.x（2026-11-07）

一次交付六项功能：

1. **重命名复原**：记录 `原名/新名/原路径/新路径`，按批次回滚
2. **合集批量删除**：`DeleteFileLocation = false`，只删条目不删媒体文件；删除前整批备份一次
3. **失效记录清理**：Jellyfin 里已不存在的合集自动从表格移除；进页自动执行
4. **改名对照表头排序**：五个表头可点，升降序切换
5. **刮削源一键添加**：粘贴网址自动推断源配置，缺 `{id}` 占位符时按「目录/{id}.json」补全
6. **任务定时**：每日启动时间可设，跨版本反射兼容（10.9 的 `Triggers` 是数组、枚举名 `TaskTriggerType`；10.11/12.4 是集合、枚举名 `TaskTriggerInfoType`）

外加按钮与标签高对比修复。

### 3.1.0.x（2026-11-07）

源名称替换只依据影片源名称，移除规则里多余的「仅路径包含」筛选条件。引擎方法签名从 `Apply(source, rules, path)` 改为 `Apply(source, rules)`。

### 3.0.0.x（2026-11-07）

首次引入**源名称替换规则**：

- 规则格式 `模式:替换文本`
- `*` 开头表示任意前缀通配
- 其余按正则
- 执行顺序固定为 重命名 → 写入名称 → 触发刮削
- 内置 `RenameLogDoc` 表记录可复原信息

**首次实现时的一个 bug**：`*@` 里的 `*` 被判定为正则元字符，`*@` 不是合法正则，匹配失败退化为字面量又找不到 `*@`，规则等于失效。已在同一版本修正：只有出现成对元字符（`[]{ }()|^$\`）或 `?`，或 `*` 跟在字符后当量词时，才走正则。

## 二、版本选择建议

| 你的情况 | 建议版本 |
|---|---|
| Jellyfin 12.4，需要全部功能 | **5.1.0.2** |
| 只需要合集 + 改名对照，不需要改文件名 | 2.1.0.2（更精简） |
| 网络盘只读、暂不需要磁盘改名 | 4.2.0.2 以上均可 |
| 需要排查命名问题 | 4.4.0.2 以上（有文件清单表） |
| 需要检查写权限 | 5.0.0.2 以上 |

**12.4 上的最小可用版本是 1.7.0.2**（1.7 之前注入页不执行脚本，按钮全部无反应）。

## 三、升级注意

- 数据（规则、合集记录、备份、重命名日志）都存 LiteDB，升级不丢
- 升级后需重启 Jellyfin
- 若界面仍是旧版，是 iframe 缓存，浏览器打开 `/CollectionStudio/Full` 后 Ctrl+F5
- 版本号可在控制台插件详情页确认，应与所选版本一致（不一致说明装的是旧包）
